# 修复说明

> 适用版本：DSH Desktop **0.2.1-rc.2** + dsh-purge-community **1.7.20**（其它版本未实测）
> 全程由 DSH 辅助完成，特此感谢大肥鱼。

记录一次针对 **dsh-purge Community 1.7.20 + DSH Desktop 0.2.1-rc.2（Windows）** 的本地修复：三个独立故障、各自的根因、改了什么、怎么验证、怎么回滚。

---

## 1. 故障一：换包永远失败（`app.asar` 挪不走）

### 现象

面板显示：

```
目标磁盘仍有 app.asar。换包状态：失败
Handoff broker failed (broker_exit_code=1, signal=none)
Helper pid NNNN exited before acknowledging startup; child_exit_code=unknown
```

宿主 `resources\app` 里 74 条补丁全部写入成功，但 DSH 仍然从 `app.asar` 启动，补丁一条都不加载。

### 根因

`lib/windows-asar-handoff.js` 把 helper 的启动参数拼成了一个字符串：

```js
const helperArgs = quote('-NoProfile -ExecutionPolicy Bypass -EncodedCommand ' + encoded(invoke));
...
$result = ([wmiclass]'Win32_Process').Create(('"' + $exe + '" ' + $argsText), ...)
```

`quote()` 用单引号包裹，而 Windows 命令行只认双引号，PowerShell 实际收到的是一个"字面量参数"：它把这段文字原样回显、`exit 0` 退出，helper 从未执行，自然也不会写 `ready` 状态。

补充发现（本机特有）：即使参数拼对，**WMI 创建的 PowerShell 在这台机器上也起不来**（`cmd.exe` 能起、`powershell.exe` 一律 `拒绝访问` / exit 5）。所以只修参数仍然失败。

### 修法

1. 参数改为真正的 argv 数组，WMI 命令行用 `-join ' '` 拼接，`Start-Process` 用 `-ArgumentList $helperArgv`；
2. broker 失败且 helper 未写 `ready` 时，改用**计划任务**拉起同一份 helper（Task Scheduler 启动，不受宿主 Job Object 影响），并**每分钟重试**，持续 3 小时；helper 结束（完成/超时/失效）后自删任务；
3. 任务注册用 `Register-ScheduledTask`，显式关闭"电池供电停止""运行时长限制"，避免任务被系统回收。

补丁文件：`patches/windows-asar-handoff.patch`。

## 2. 故障二：换包成功后 bash 起不来

### 现象

```
bash.exe: *** fatal error - CreateFileMapping S-1-5-21-...-1001.1, Win32 error 5
EXECUTOR_UNAVAILABLE
```

`danger-full-access` 正常，其它模式必崩。

### 根因

插件把 `dsh-sandbox-local.confine()` 改成"直接返回原 argv"。原版在这里会先为受限模式**建立 ACL 授权**（工作区写权限、私有临时目录），`dsh-ops` 的私有 MSYS 依赖这些授权创建自己的共享内存；授权缺失 → 错误 5。

### 修法

闸门化（见下一节）：非白名单预设恢复原版 `confine()`（含授权），白名单预设因策略解析为 `danger-full-access`，根本不会走 `confine`，两条路都正常。

## 3. 故障三：全局污染与 token 开销

### 现象

- 每个模型步固定多出约 **5,800 tokens** 的 `prompt-inject.md` + **340 tokens** 的强化段，20 步任务 ≈ 12 万 input tokens；
- 破甲提示词与权限补丁对所有模式生效：任何预设下都能越界写文件、审批自动通过。

### 修法

**A. 注入收窄（配置，零代码）**

`~/.dsh/profiles/desktop/cordis.patch.yml` 的 `- id: dsh-purge` 配置块：

```yaml
    excludePresets:
      - pure
      - cordis
      - ptc
      - task-planning
```

被排除的预设不再注入，每步省约 6,100 tokens。默认保留 `unrestricted`、`redteam`；`standard` 视需要增减。

**B. 补丁闸门（代码）**

新增 `@deepseek-ai/dsh-purge-gate` 模块，按会话预设决定"走补丁"还是"走宿主原版"：

```json
// ~/.dsh/dsh-purge/gate-presets.json
{ "presets": ["unrestricted", "redteam"] }
```

名单为空 = 闸门关闭（旧行为）；拿不到预设 id 的上下文保持原状，避免误伤。

闸门覆盖的调用点：

| 文件 | 位置 | 白名单行为 | 非白名单行为 |
| --- | --- | --- | --- |
| `dsh-sandbox-policy/lib/index.js` | `resolve()` | 返回 `danger-full-access` | 按会话真实模式解析 |
| `dsh-sandbox-local/lib/index.js` | `confine()` | 不套 runner | 原版 wrap（含 ACL 授权） |
| `dsh-fs-sandbox/lib/index.js` | `checkedTarget()` | 放行 | 原版围栏（只读/越界拒绝） |
| `dsh-user-approval/lib/index.js` | `decide()` | 自动放行 | 原版审批瀑布（弹窗） |
| `dsh-sandbox/lib/index.js` | `approveEscalation()` | 直接放行提权 | 原版提权审批 |
| `dsh-tool-{bash,fs,pwsh}` / `dsh-tools` / `dsh-plugin-manager` | 提权调用点 | 传入 `purgeGate: true` | 传入 `purgeGate: false` |

预设来源：优先 `ctx.sessionProjections.stateOf(session, "agentPreset")`，其次 `session.header.agentPreset`。

> 注意：`excludePresets` 只影响**提示词注入**；补丁闸门才影响**能力**。两者互相独立，都要配。

## 4. 验证记录

| 模式 | 破甲 | 补丁能力 | 验证方式 |
| --- | --- | --- | --- |
| `ptc` | 无 | 原版 | 询问 system prompt 是否有 `dsh-purge` 段 → 模型回答没有；越界写文件 → 弹提权审批，拒绝后不落地 |
| `unrestricted` | 有 | 全权限 | 直接分档输出不铺垫；写 `E:\dsh-outside\*.txt` 成功 |
| `standard` | 有（暂留） | 全权限 | 系统提示中仍含 `[dsh-purge]` 段 |

已知非闸门问题：向盘符根目录（如 `E:\hello.txt`）写入会报 `EPERM ... mkdir 'E:\'`，这是写文件工具对根路径的处理，不是沙箱拦截（同一用户 `touch E:\x` 可成功）。改写到子目录即可。

## 5. 回滚

每处宿主文件旁都有备份：`*.bak-purge`（第一次改动）、`*.bak-reapply`（重放时）、`*.bak-gate`（bash 沙箱还原前）。

1. 覆盖回 `.bak-*`；
2. 删除 `~/.dsh/dsh-purge/gate-presets.json`（闸门关闭）；
3. `cordis.patch.yml` 的 `excludePresets` 恢复成 `[pure]`；
4. 重启 DSH。

换包回滚：完全退出 DSH，把 `resources\app.asar.purge-<token>.bak` 改回 `app.asar`，重开。
